Portable project memory, structured state, and zero hallucination.

Continuity is not loose “vector memory”. It is a deterministic, portable source of truth about the work—built on Markdown + Git + Filesystem and indexed with SQLite FTS5.

Structured Repository Memory (`.continuity/`)

Active plan, current task checklist, Git history, session summaries, ADRs, and handovers.

Global Developer Context (`~/.continuity/`)

Developer preferences, machine specs, global toolchain defaults, and cross-project knowledge.

Permanent Failure Registry

Never let an agent repeat an approach that previously failed. Document once, protect forever.

What makes Continuity the right partner

Engineered from first principles for developers who demand real predictability instead of stochastic memory promises.

Pillar 01

Deterministic Git & Filesystem

No proprietary cloud locks or opaque vector embeddings. Everything lives in plain Markdown and Git commits. You can inspect, diff, commit, and edit every piece of state with vim or git.

Pillar 02

Two-Memory Layer Architecture

Clear separation of concerns: Global Memory (`~/.continuity/`) for machine defaults and engineering patterns; Project Memory (`.continuity/`) for repository-specific plans, ADRs, and checklists.

Pillar 03

Zero-Config Universal Adapters

Native support for Claude Code (`CLAUDE.md`), Cursor (`.cursor/rules/`), Windsurf (`.windsurfrules`), Cline (`.clinerules`), and Antigravity. One setup works seamlessly for all.

Our method for autonomous AI continuity

A simple, reliable three-step loop that turns any agent session into persistent engineering value.

Step 01

Resume Context

Run `continuity resume`. The engine parses Git status, active plans, task progress, and ADRs, returning an exact briefing to the model.

$ continuity resume
Step 02

Execute & Document

Work according to the active plan step. If an approach fails, log it immediately with `continuity failure record` so it's permanently remembered.

$ continuity failure record "title"
Step 03

Handover State

Run `continuity handover`. The current state, commit diff, and next actions are packaged for whoever opens the project next.

$ continuity handover
